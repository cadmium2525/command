# SECRET START ゲーム設計

## プレイとタイトルの順序

3文字のコマンドから始まる、173種類の短いアーケードゲームです。当たりのコマンドはすべて操作できるゲームを起動します。ゲーム中は課題と操作を案内し、ゲーム終了後にタイトルを明かします。遊んだ内容とタイトルが結び付くことを、結果画面のオチにします。

1. ↑・↓・←・→・A・Bを3回入力し、STARTで確定する。
2. 試行と発見を保存する。
3. 対応するルールと操作を表示し、ゲームを開始する。
4. 方向キーとA/Bで、実際に盤面や自機を操作する。
5. 勝敗の確定または制限時間で終了し、スコア・終了理由・タイトルを表示する。
6. 結果は自動で閉じず、明示的な戻る操作を待つ。

進行中にゲーム名が先に見えないよう、見出し、キャンバスの説明、読み上げ通知、進捗説明にも課題・操作を使います。タイトルは結果表示で使用します。開発用カタログと管理者向け資料は、確認のため全タイトルを掲載するネタバレ資料です。

全収集対象に`GameEvent.game`があり、動画だけを再生する対象はありません。スコアや勝利数は発見の条件に使いません。途中終了・失敗でも、そのコマンドを見つけた事実は保存します。

## 画面と入力

通常画面にはゲーム機だけを置きます。キャンバス、ルールと結果、3つの入力枠、方向キー、A/B、START、削除、入力リセット、5つのメニューボタンをゲーム機内に収めます。

図鑑、探索、記録、設定、管理はネイティブ`dialog`で開きます。表示中は背景操作とゲーム時計を止めます。閉じたら元のゲームへ戻り、開く前のボタンにフォーカスを戻します。閉じるボタン、Escape、ブラウザーの戻る操作に対応します。

コマンドは同じ記号を繰り返せます。3枠が埋まるまでSTARTは無効で、4文字目は保持しません。削除は1文字戻し、入力リセットは入力枠だけを空にします。キーボードは矢印、A/B、Enter、Backspace、Deleteに対応します。検索欄などの入力にゲーム用ショートカットは割り込みません。

ゲーム中の方向キーとA/Bは、現在のエンジンへ入力を渡します。長い説明文を読み進める操作には使いません。個別の操作と勝利条件は、エンジンが持つ`controls`と`rule`をそのまま表示します。

## データとエンジンの契約

`src/events/arcade-types.ts`が共通契約です。`ArcadeDefinition`には`family`、0始まりの`variant`、結果で明かす`title`、プレイ中に表示する`rule`と`controls`、制限時間`durationMs`があります。

`arcade-physical.ts`の`PHYSICAL_DEFINITIONS`と、`arcade-skill.ts`の`SKILL_DEFINITIONS`がメタデータの原本です。カタログはこの定義オブジェクトを直接参照し、タイトルやルールの別コピーを作りません。合計が173件でない場合は起動時に検出します。

`ArcadeEngine`は以下を提供します。

- `input(key)`：方向キーまたはA/Bを受け取る。
- `update(dt)`：秒単位の経過時間でゲームを進める。
- `draw(ctx, palette, reducedMotion)`：320×200のプレイ画面を描く。
- `score`：現在の得点。
- `outcome`：進行中は`null`、終了時は`win`・`lose`・`time`と理由。
- `snapshot`：テストや確認に使えるゲーム状態。

プレイヤーがゲーム時計・入力・描画・終了通知を担当します。モーダルや画面離脱中の一時停止で、復帰直後に時間が飛ばないようにします。終了したゲームは進行を止め、結果を読むまで待ちます。中断した盤面やプレイ途中のスコアは、収集セーブには保存しません。

旧連携用の`category`、`durationClass`、`mechanic`、`timeline`などは型に残します。全173件の`category`と`durationClass`は`minigame`、`mechanic`はジャンル名です。`timeline`は操作説明の`play`一件で、物語再生には使いません。ゲーム描画の素材参照は、既存のコード描画`world`を使います。

## コマンドと保存の互換性

入力は6³＝216通りで固定です。173個をゲームへ1対1で対応させ、残り43個を空振りとします。乱数や外部通信で当たりの配置を変えません。

旧173件のIDとコマンド対応をそのまま使います。内部IDの`remix-001`〜`ending-005`は保存用の住所であり、今のジャンルではありません。新ゲームの表示分類は、`game.family`を使います。

コマンド割り当ては元の固定置換と予約枠を維持します。`UUU`→`remix-001`、`AAA`→`remix-002`、`DDD`→`story-001`、`BBB`→`ending-001`も変えません。保存データはIDを持つので、旧版の発見・閲覧・お気に入りは対応する新ゲームへ引き継げます。

`tests/catalog.test.ts`は、旧173組と全216判定の固定SHA-256、全18ジャンルの件数、バリエーションの連続性、全173タイトルと定義キーの重複、原本メタデータへの直接参照を確認します。

## 管理者プレビューと通常モード

管理者モードは初期ONです。全173件の試遊と全216コマンドの確認ができます。プレビューでは、発見数・入力済み・閲覧済みの収集記録を増やしません。タイトルでコマンドを実行した場合は、管理者モード中でも通常の発見として保存します。

管理者OFFでは以下の条件を使います。

| 実際の発見数 | 通常モードの変化 |
| ---: | --- |
| 0〜4 | 図鑑と探索一覧の解禁条件を表示 |
| 5 | 発見済みゲームの図鑑、検索、お気に入り、再プレイ |
| 87 | 216枠の探索一覧 |
| 173 | 完集ボーナスゲームを開放 |

通常の探索一覧は、未入力、発見済み、空振りを表示します。未入力の内容と当たり外れは伏せます。項目からコマンドを3枠へセットできます。

管理者表示は`secret-start.admin-preview`へ独立して保存します。収集記録を消してもON/OFFを変えません。静的サイトの表示設定で、認証による保護機能ではありません。

## 完集ボーナス

`true-ending`は173件とは別の短い反射神経ゲームです。操作とルールは`reaction`の`variant: 0`を参照し、結果で全発見を祝います。収集枠やコマンドを消費せず、記録画面から再プレイできます。

## 保存と共有

`secret-start.save`に`schemaVersion: 2`の入力履歴、発見、閲覧、お気に入り、設定、完集案内状態を保存します。発見はゲーム開始前に確定します。不正値と重複を除き、既知のIDとコマンドだけを採用します。v1の配列名からも移行します。

破損・将来形式の原本は`secret-start.save.recovery`へ退避してから新しい記録を書きます。退避できなければ原本を保持し、メモリー上でプレイを続けます。別タブの発見は統合し、明示的な全消去は別タブにも反映します。

設定から1MB以内のJSONを読み込み、既存記録と統合できます。書き出しはJSONダウンロード、全消去は2段階の確認です。消音、動きの削減、端末の動き削減設定に対応します。X共有は記録画面から投稿確認画面を開き、利用者が確定します。

## 描画と配信

ゲーム本体はローカルのコード描画で動作します。320×200の論理キャンバスを拡大し、日本語の課題・操作・結果はHTMLで表示します。タイトル画面の同梱画像には、読み込めない場合のコード描画も用意します。

音は最初の操作後にWeb Audioで鳴らし、消音・画面離脱・モーダル閲覧時には止めます。外部フォント、分析サービス、サーバー、DB、認証、課金APIを必要としません。

本番ファイルは`dist/`です。ビルド時にローカルファイルのハッシュと事前キャッシュを生成し、HTTPSまたはlocalhostの初回読み込み後にオフラインで使えます。GitHub Pagesのbaseと共有URLはビルド時に設定します。

この資料は新仕様の設計と実装契約を記載するものです。新実装の検証結果は、テストとビルドを実行した出力で確認します。
